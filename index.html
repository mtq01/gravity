What Orbit is Built With

Orbit catches real, fixable issues fast, but it can't tell you if your alt text actually makes sense, or if your interface is genuinely usable with a screen reader.

Features

  • Automated Violation Scanning

    Real-time WCAG audits, powered by axe-core. Point it at any page and see every automatically-detectable violation, ranked by severity. Things like missing labels, low contrast, and invalid ARIA. This is a fast first pass, not a full audit.

  • Tab Order & High Contrast

    Some issues can't be scanned, only seen. A numbered overlay traces keyboard focus order across the page, and high contrast mode previews low-vision rendering, surfacing the kind of problems no rules engine catches.

  • Color Contrast Checker

    Pick a foreground and background color and get an instant AA/AAA verdict against WCAG 2.2 thresholds, useful for validating a design decision before it ships.

  • A11y Project Checklist

    Automated scanning has real limits. This tab surfaces The A11y Project's community-maintained checklist, the manual, human-judgment checks that fill in what axe-core can't see.

About Orbit

Built on open standards, not guesswork.

Orbit doesn't invent its own accessibility rules. It's built on axe-core, the same engine used by major testing tools industry-wide, and pairs it with WCAG 2.x contrast math and The A11y Project's community-maintained checklist, so what you see in Orbit reflects established, peer-reviewed accessibility guidance.

  • Axe-core

    The open-source accessibility testing engine that powers Orbit's automated scans, built and maintained by Deque Systems and used across the industry.

  • WCAG Guidelines

    The Web Content Accessibility Guidelines. The official W3C standard that defines what "accessible" means, and the benchmark Orbit's contrast checker and scanner test against.

  • The A11y Project

    A community-driven effort making web accessibility easier to understand, with practical resources and the checklist that powers Orbit's manual audit tab.

Methodology

Orbit automates what can be reliably automated, and is explicit about the rest. Automated tools like axe-core are excellent at catching objective, rule-based violations, but a meaningful share of WCAG success criteria require human judgment. Orbit is built around that line, not around pretending it doesn't exist.

What's Automated

  • Missing or empty alt attributes
  • Insufficient color contrast ratios
  • Missing form labels
  • Invalid or misused ARIA attributes
  • Missing document landmarks
  • Duplicate IDs
  • Missing page language attributes
  • Heading structure issues (ex. skipped levels)

What Needs a Human Touch

  • Alt text accuracy and meaning, not just presence
  • Logical reading order for screen reader users
  • True keyboard operability of custom widgets
  • Clarity of error messages
  • Content that makes sense out of visual context
  • Intuitive interactions for screen reader and switch device users
  • No automated scanner, including Orbit, can verify these.
